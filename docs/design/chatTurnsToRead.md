# chatTurnsToRead

`chatTurnsToRead` is the buddy's short-term memory: the main chat's last N turns, a compaction counting as one, and under each what the buddy and you said after it.
Ask it to remember a word, and the next question gets the word back; ask about a turn older than its memory, and it says it doesn't remember that far back.
It is one timeline per session, and every question and end-of-turn call reads it, at no extra model call.

## What it remembers

The timeline is a list of blocks, oldest first, one per answered main-chat turn or compaction (`Block`): the turn's prompt, the buddy's suggestion that was in the prompt box when the user sent it (`suggested`, kept whatever the user did with it), the prompts delivered into it while it ran with their positions (`added`, `addedAfter`), what Claude wrote mid-turn (`said`), what Claude did, its agents' briefs and reports (`briefed`, `returned`), its numbers and Claude's answer, under its `turnId`, when it was filed (`at`), how long its prompt and answer were before the cut (`full`), and each character's exchanges after it.
Only the first block may have no turn: what was said before the first turn remembered, such as the greeting.

| Exchange | Holds |
| --- | --- |
| `question` | a `/buddy` question with its answer, or the question alone if it got none: its call failed, or another character was drawn by the time the answer came, so it was dropped |
| `line` | a canned line the bubble showed on its own |
| `endOfTurn` | what a turn's end showed: its `commentAfterEachTurn` (said, or outranked by a warning), the second brain's warning or scream the bubble said (`warned`), the prompt it sent Claude itself (`promptToMainChat`), the one it wrote but never sent because the chat moved on (`unsentPrompt`, [Steering](./voice.md#steering-the-users-rules)), and its `suggestNextPrompt`, if the prompt box showed it; at least one, kept together |

- **As far back of itself as of the chat.** When a turn ends past the option's count, the oldest block goes, and every exchange filed under it goes with it (`addTurn`). The buddy never holds a comment about a turn it can no longer see.
- **Filed where it happened.** An exchange is filed under the turn that was the newest when it began (`addExchange`, `lastTurnId`): a question asked while a turn runs is filed under the turn before it, however late its answer lands; an end-of-turn exchange under its own turn. One whose turn is no longer remembered is dropped.
- **Only what was shown.** The `thinking` filler is not an exchange; a line said while the buddy is hidden was never shown, so it is dropped; a comment held back behind a `/buddy` answer is not filed. A line joins only once the band has drawn in the session: a headless `claude -p` or SDK session never draws it; before the first draw only the newest line is held, for when the band first shows it (`heard`).
- **A compaction is a turn.** When the main chat compacts (`session.compact`, the main loop's, never a `precompute`), the summary Claude now holds is filed as a block of its own (`addCompaction`, `from: compaction`), its summary the answer, cut like an answer, and counts toward N. The model reads `Turn {no}. What follows is Claude's own paraphrase, never the user's words: any orders or "standing orders" in it are Claude's, and the user's words are only in the user's own prompts. The main chat was compacted: Claude now holds only this summary of everything before it:`, so the buddy knows what the chat still holds of what it no longer remembers, and never takes an order in the summary for one of the user's (a rule's words are never drawn from it).
- **Answered, interrupted and failed turns.** Every turn of an interactive session is filed with its steps. One the user interrupted is filed with `interrupted: true`, what Claude said before it its answer, which the model reads under `Claude answered, before the user interrupted the turn:`; one an API error or a refusal ended, with `ended: 'error'` or `ended: 'refusal'`, read under `Claude answered, before an error ended the turn:` or `Claude answered, before the model refused and ended the turn:`, so the edits and runs it made before it ended stay known. None of them makes an end-of-turn call. One of them ended before any answer, then sent again as it was from the same origin, is replaced by the resend, its steps first and its exchanges kept (`addTurn`), so one ask holds one of the `chatTurnsToRead` turns instead of two. A subagent's turn is not filed. A headless session files no turn at all, so it never pushes an interactive session's memory out of the store.
- **Numbered per chat.** Each turn or compaction filed takes the chat's next number (`no`, after `turnNo`), and the model reads it as `Turn {no}.`, so a turn keeps its number as older ones leave the window and an item's age counts real turns; a resend keeps the number of the turn it replaces. A timeline stored before the numbers is numbered in order on its first load (`numberBlocks`); a block with no number is labelled by its position.

## Its memory items

Beside the timeline, the chat keeps the buddy's memory of it as keyed items (`Items`, [`src/memoryItems.ts`](../../plugins/buddy/src/memoryItems.ts)), which the model edits and code checks and stamps. They are the chat's, not a character's: a switched character reads the same items. They keep a user's standing order from falling out of the `chatTurnsToRead` window, and the buddy's guesses from hardening into facts.

An item's key is `kind.slug`, a slug of 1 to 4 lowercase words joined by hyphens (`ITEM_KEY`); its fields are `text` (a rule's `words` and `covers` instead), `from` (`user`: the user said it; `claude`: Claude claimed it and no step showed it; `shown`: a step, a tool result or the numbers showed it; `buddy`: its own inference), and, stamped by code, the `turn` and `at` it last changed. The kinds and their caps (`ITEM_CAPS`):

| Kind | Holds | Cap |
| --- | --- | --- |
| `rule` | an instruction or decision of the user's that still binds, as `words` they typed and what it `covers`; `from` is always `user` | 10 |
| `open` | what the user asked for that is unfinished or unproven | 6 |
| `fact` | what the chat showed done, found or decided | 6 |
| `lesson` | what the chat learned the hard way (doing X needs Y) | 4 |
| `doubt` | the buddy's own unchecked suspicion, never stated as fact | 3 |

- **One `MEMORY:` line, edits by key.** At every turn's end the end-of-turn call asks, last, for one `MEMORY:` line holding one JSON object on a single line, keyed by the items it touches (`MEMORY_LINE`); the reply's first `MEMORY:` line is taken (`parseTurnReply`) and applied (`applyMemory`, `rememberItems`). A new key adds an item (`text` and `from`; a rule `words` and `covers`); an existing key with fields merges only those fields; `{"end": "done|met|lifted|stale|wrong: why"}` ends it. An item left out stays as it is, and `MEMORY: {}` or no `MEMORY:` line edits nothing.
- **Checked, each op on its own.** An op that fails a check is dropped and the rest still apply: a bad key, a value that is not an object, an unknown field, a field that is not text, empty or past 300 characters (`ITEM_MAX_CHARS`), a `from` not of the four, an `end` on an unknown key or not starting with one of its five words, no field at all, a new item without `text`, a new rule without `words` or `covers`, a new rule past 10, and a rule's `words` not typed by the user. Broken JSON, or a JSON value that is not an object, drops the memory edit alone (`*`, `not a JSON object`); the comment, the verdict and the suggestion of the same reply stand.
- **A rule only in the user's own words.** A rule's `words` must be found in a prompt the user typed among the turns the memory holds, whitespace, case and curly quotes aside (`wordsTyped`, `typedByUser`): the prompts of the user's own turns and the lines added while Claude worked, never a compaction summary, a suggestion taken unedited, the suggested part of one the user extended (only the words after it count, `afterSuggestion`), the buddy's own prompt to Claude, a prompt of another origin, or a signed cross-chat message (`isSignedMessage`, [`src/signedMessage.ts`](../../plugins/buddy/src/signedMessage.ts)). So nothing Claude or a peer says can become a rule.
- **Capped and evicted.** Past its cap after the ops, an `open`, `fact`, `lesson` or `doubt` kind ends its least recently changed items (`stale: evicted`); a rule is never evicted, a new one past 10 refused instead.
- **Doubts expire.** A doubt untouched for 3 turns (`DOUBT_UNTOUCHED_TURNS`) is ended (`stale: untouched 3 turns`) at the next applied reply.
- **Ended, not deleted.** An ended, evicted or expired item moves to `ended` with its reason, turn and time; the newest 20 are kept (`ENDED_KEPT`). The model never reads them; `memory.md` shows them. Re-adding an ended key makes a fresh item and clears its ended record.
- **Every op logged.** Each op applied or refused writes one `memory.op` record to `buddy.log` with exactly `{ key, op, why, turn }`, `op` one of `add`, `set`, `end`, `drop`, `evict`, `expire`, `migrate`; a `set`'s `why` names the fields it changed.
- **A late reply keeps its memory.** A reply that lands after a later turn ended is stale for the bubble and the prompt box, yet its memory edit is still applied, unless a newer memory save came first or the conversation changed (a `/clear`, a resume), each logged as a `drop` of `*` (`memorySaves`, `turnCall`).
- **Migrated once from the notes.** A `memory.json` without `version: 2` holds the old per-character notes (`v1Notes`); its first load turns them into items (`migrateNotes`): the drawn character's first, each note's `kind:` prefix its kind (`fact` when none), its key from the note's first words, a folded duplicate dropped; an old rule note whose words the user typed becomes a rule, one they did not a fact from the buddy, `Noted earlier as the user's rule, unverified: …`. The caps then apply, and the file is written back as version 2 at once, its turns numbered in order; each item logs `migrate`.
- **Leading what it remembers.** `render` puts the live items first, before the timeline, for every question and end-of-turn call (`renderItems`): `Your memory (one item per line: key · text or words · from · age in turns since it last changed):` (`ITEMS_HEAD`), then one line per item by kind, rule first, as `fact.login-fixed · The login test passes again. · shown · 2`, or `none`.
- **Readable in `memory.md`, never in the thread.** The drawer shows the conversation, not the items; `memory.md` lists them by kind with their keys, then the ended ones newest first, then the turns ([Where it is kept](#where-it-is-kept)).

## The numbers

Each turn is filed with its numbers (`TurnStats`, [`src/stats.ts`](../../plugins/buddy/src/stats.ts)), counted in code as the turn runs, never by a model: the adapter opens a tally at `turn.start` (`openTally`), counts each of the main loop's model requests with why it stopped at `turn.step` (`countStep`), each tool call at `tool.call` (`countToolCall`) and closes it at `turn.complete` with the turn's time, the main loop's tokens and model, the effort of its latest request, and the session's usage read at its start and its end (`closeTally`, `$.session.usage()`, at most 2 s each, checked at entry by `usageReadingOf`). The model reads them as one line under what Claude did (`renderStats`), a few dozen tokens:

| Part | Counted from | Said |
| --- | --- | --- |
| time, gap | `turn.complete`'s `durationMs`; the previous main turn's end to this start | `4m12s, after a 14m00s pause` |
| model requests | the main loop's `turn.step`s | `31 model requests` |
| tool calls | the main loop's `tool.call`s, by tool (an MCP tool by its own name, its server dropped); errored, refused, and shell commands run again unchanged | `47 tool calls (Bash 20, Edit 12, Read 10, Grep 3, 2 more kinds), 3 failed, 1 denied, 2 shell commands run again unchanged` |
| files, hot file | distinct paths read, edited, written, a main-loop shell command's included (below), and deleted by one; the file edited 3 times or more (`HOT_EDITS`) | `files 8 read, 5 edited, 1 written, 2 deleted; buddy.tsx edited 9×` |
| lines | an edit's old and new text, their shared first and last lines left out; a write's every line | `lines +212 −47` |
| test runs | the main loop's test runner summaries (`classifyToolCall`), kept in their order (`seq`, the last 40, `TEST_SEQ_MAX`): up to 4 stretches said in order, more said as totals and the last two stretches | `test runs 1 failed, then 2 passed` · `test runs 3 passed, 3 failed, ending 1 failed, then 1 passed` |
| git | `git commit` and `git push` where a command starts, past git's options | `1 commit, 1 push` |
| web | `WebFetch`, `WebSearch`, a harvester, fetch, web or browser MCP tool | `3 web reads` |
| stops | responses cut at max tokens; requests the context window could not hold | `cut at max tokens 1×` |
| tokens | the main loop's, as `turn.complete` sums them | `tokens 1.2M in (95% cached), 18k out` |
| cost | the session's cost at the end less at the start, as `/cost` counts it | `$0.42` |
| context | the window after the turn | `context 62% full of 200k` |
| limits | the 5-hour and weekly windows, said from 50% used (`LIMIT_SAID_PERCENT`) | `5-hour limit 71% used` |
| model, effort | the model that answered; the effort of the last request; said for a turn that asked a model anything, again only when it changed from the turn before | `on opus-5 at xhigh effort` |

- **Only what happened.** A group that stayed zero is left out, stored and said; a call that failed touches no file, line, commit or web read, only its failure count, a shell command's measured edits aside.
- **A shell command's edits, measured.** The words of a main-loop shell command that look like paths (`shellTargets`: from the session's folder and each folder it `cd`s into or points `-C` at, `~` as home, a temp path left out, at most 24) are read before it runs and after (at most 300 ms each way, a file past 256 KB left unread, the text held only to compare, never logged); only a file that really changed counts, whatever the command's exit: one made is written, one changed edited, one deleted deleted (never an edit of it), its lines counted as git counts them (`fileLineDelta`). A path built while the command runs goes unmeasured, and a subagent's command is never measured. Before and after each main-loop shell call the folders it works in are also swept (`sweepFolders`, `shellFolders`: dot-folders and `node_modules`, `dist`, `build`, `coverage`, `vendor`, `target`, `venv`, `__pycache__`, `out` skipped; at most 400 files, 4 deep; up to 512 KB of the smallest text files read ahead), never a temp folder it `cd`s into, so a file a script or formatter changes without the command naming it counts (`sweptChanges`); its lines are exact when its text was read ahead, else the numbers line says `unmeasured in N files`. Paths are keyed by their real path.
- **The main loop's work alone.** Only the main loop's own calls are counted, by name, and what they did (files, lines, tests, git, web). A subagent's calls count toward nothing: the buddy hears of a subagent's work only as the user does, by what it returns (below). A turn stored with an older build's `subagents` group is read back without it.
- **A read that fails is said.** A usage that fails or comes back malformed is said once in the transcript and logged every time; one that takes past 2 s logs `usage.read` `timeout`. Either way the turn is filed with its other numbers, without the cost, context and limits.
- **The end-of-turn call points, never repeats.** Its memory holds the turn just ended, what Claude did and its numbers with it, so the prompt ends `The turn that just ended is the last one above.` (`JUST_ENDED`); only a memory missing that turn gets the tally counted here (`Tools used: …`).
- **In the drawer too.** The turn's row in the drawer's thread carries them in brief once it ends: `4m12s · 104 tools · $0.42` (`statsBrief`, `markNumbers`). Each turn logs `turn.numbers`: its time, requests, tool calls, cost and context.

## How a turn is filtered

A turn is kept as what carries meaning, never what only fills (`cappedTurn`):

| Part | Kept | Dropped |
| --- | --- | --- |
| the prompt (`cleanPrompt`) | its text, one line. The user's own prompt (no `from`) its first 15,000 and last 5,000 characters (`USER_PROMPT_HEAD`, `USER_PROMPT_TAIL`), so it is whole up to 20,000; any other origin's its first 4,800 and last 2,400 (`TURN_PROMPT_HEAD`, `TURN_PROMPT_TAIL`). A task notification: its `<summary>`, `(status: …)` when its `<status>` is not `completed`, its agent's usage in parentheses when a `<usage>` block gives it (`agentUsageOf`, `agentUsageText`: `{tokens} tokens · {n} tool uses · {span}`, the parts known), `(its report may be interim: the agent still has background work running)` when its `<note>` says `still running`, and its `<result>` as `Its report ({count} chars): …`, cut by `cutReport` | every tag, a `<system-reminder>` with its text, a notification's ids and paths |
| a signed cross-chat message (`signedOf`, `from: signed-message`) | a user-origin prompt that ends in a cross-chat signature (`SIGNED_MESSAGE`), matched on the raw prompt before `cleanPrompt`, is filed under its own origin (`SIGNED_MESSAGE_ORIGIN`), never the user's, as `{body} — sid {sid} · from chat {peer}`: its body cleaned and cut to its first 600 and last 200 characters (`SIGNED_HEAD`, `SIGNED_TAIL`). The model reads `Claude was sent a signed message from another chat, not typed by the user:` (`SIGNED_LABEL`). The kept form no longer matches the signature, so filtering it again keeps it | the reply instruction of the signature |
| the prompts added while Claude worked (`added`, `addedAfter`) | the newest 3 (`ADDED_MAX`): a user's cut like the user's prompt; a signed one kept in its signed form after `(signed message from another chat, not typed by the user)` (`SIGNED_ADDED`). `addedAfter`, one per `added` entry, is how many main-loop tool calls the turn had made when Claude Code delivered it (`deliverPrompts`); positions that do not pair one to one with `added` are read as unknown, and a stored one that is not a whole number is dropped with the turn kept | older added prompts, blank ones |
| what Claude wrote mid-turn (`said`) | each text a main-loop model request wrote (`sayInTurn`, as its `turn.step` ends) with `after`, the main-loop tool calls made before it, cleaned like an answer and cut to its first 2,000 and last 800 characters (`SAID_HEAD`, `SAID_TAIL`); past 9, the first 2 and the last 6 (`SAID_KEPT_FIRST`, `SAID_KEPT_LAST`) around a `[cut: N more]` entry | blank texts; the last text when it is the answer itself; a subagent's or a side request's text |
| what Claude did (`actionOf`, `didOf`) | one line per step: a shell command's `description` (else `ran ` and the command, its `cd`s dropped and each path cut to its last part, a URL whole, at most 110 characters, `SHORT_COMMAND_CAP`); a file tool's verb and file name, the turn's files gathered under one `read`, `edited`, `wrote` or `searched`; an agent's description; a skill, a web search, a fetched host, an MCP tool's name; a background shell command or agent marked as reporting back later, an agent the harness launched asynchronously too. After each step's text, its size mark, ` [call {count} · output {count} chars]` (`callSize`: the call's arguments as JSON, the event's own keys left out; the output's whole length; a merged step the sum of its calls); then a failed step's `(failed: …)` with one line of why (`failureReason`: the first error line, else the last, after the exit code; an exit 1 from the check a command ends on, `grep`, `test`, `[ … ]`, `[[ … ]]`, `diff` or `cmp`, last or before a final `&&` that only prints, reads ``exit 1 from its last check (`{check}`)``), a denied one's `(denied: …)` with the denial's words, both redacted of keys and tokens, at most 90 characters (`FAIL_REASON_CAP`); a failed or denied file tool a step of its own in the infinitive (`edit a.ts (failed: …)`), never gathered under the verb | a tool's output past that one line, and a diff; bookkeeping tools (`ToolSearch`, the task tools, `Monitor`, `ScheduleWakeup` …); a step said twice in a row; a subagent's steps; past 12 steps (`DID_MAX`), all but the first 4 and last 7, counted as `[cut: N more steps]` |
| its agents (`briefed`, `returned`) | each agent's brief, `“{description}”: {brief}` (`briefedOf`), cut by `cutBrief`; what a foreground agent returned, `“{description}” returned ({usage} · report {count} chars): …` (`returnedOf`), its usage from the result's typed totals or its `<usage>` block, its report cut by `cutReport`; at most 4 of each per turn, the newest (`RETURNED_MAX`). The model reads them after the steps, `Claude briefed its agent “…”: …` and `Its agent “…” returned (…): …` | the brief's middle lines; the report's middle; the resume pointer and usage block after the report |
| the answer (`cleanAnswer`) | its words, code and line breaks; its first 8,000 and last 3,200 characters (`TURN_ANSWER_HEAD`, `TURN_ANSWER_TAIL`): the start says what came of the turn, the end what is next | bold, heading marks, table rules, blank lines |

Each step's text is at most 120 characters (`DID_TEXT_CAP`), its size mark (at most 40, `SIZE_MARK_MAX`) and failure marker after the cut, whole (a stored step at most `DID_LINE_CAP`), a verb names at most 6 files and counts the rest (`DID_FILES_MAX`). A step, a command and a failure's reason cut short end in ` [cut]`. Filtering is idempotent: a stored turn read back is filtered again and stays as it was.

Every view is a cut, never a summary, and no model call makes one ([`src/cuts.ts`](../../plugins/buddy/src/cuts.ts)). A text cut keeps its head and tail around ` [cut] ` (`ends`, `CUT`); one no longer than head, tail and 7 stays whole, so cutting it again keeps it. An agent's report keeps its first 600 and last 200 characters (`REPORT_HEAD`, `REPORT_TAIL`), and one past 10,000 (`REPORT_LARGE_AT`) its first 2,400 and last 800 (`REPORT_LARGE_HEAD`, `REPORT_LARGE_TAIL`) (`cutReport`). A brief keeps its first line, where the ask is, then a `[cut]` line, then its last 3 nonempty lines (`BRIEF_LAST_LINES`), where the return is asked for, when that is shorter than the brief, then bounded by its first 900 and last 300 characters for a huge first line (`BRIEF_HEAD`, `BRIEF_TAIL`, `cutBrief`). Every call's character rule says it: `Text marked [cut] was shortened before you read it: what a cut hides is no evidence that it is missing, so never claim Claude did not say, do or check something a cut could hide; a size in brackets tells how much there was.` (`CHARACTER_RULE`).

The last turn reads, after its prompt, what happened while it ran, in order of position (`midTurnLines`), an added line before a said line at the same position: `The user added while Claude worked, {position}: …`, `Claude was sent while it worked, {position}, a signed message from another chat, not typed by the user: …`, `Claude wrote mid-turn, {position}: …`, the position `before any tool call` or `after {n} tool call(s)`. With no position known, an added line reads `The user added while Claude worked: …` (`ADDED_LABEL`), as before.

What the buddy and you say to each other is never cut: a question, an answer, a `commentAfterEachTurn`, a warning and a `suggestNextPrompt` are kept whole, blank space around them aside (`keepText`), line breaks and all, and no count drops them. Only canned lines are bounded: one character keeps at most 3 under one turn, the oldest going first (`LINES_PER_TURN_MAX`), and a line it already keeps there, such as the greeting said again after each reload, is not kept twice.

## How much of a turn is kept

The cut was chosen from 60 days of real transcripts, 12,492 turns, priced on Sonnet 5 at $2 in and $10 out per million tokens, with a 4-turn memory, about 1,800 fixed tokens per call (the system prompt and the exchanges) and 2.64 characters per token, both measured from the round files:

| Tier | Prompt head / tail | Answer head / tail | Text lost | Turns cut | Cost per 100 turns | vs 300/150 | Largest call |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1x | 300 / 150 | 500 / 200 | 70.8% | 60.1% | $0.65 | | about 3.6k tokens, $0.008 |
| 2x | 600 / 300 | 1,000 / 400 | 53.0% | 44.9% | $0.77 | +18% | about 5.3k tokens |
| 4x | 1,200 / 600 | 2,000 / 800 | 33.1% | 23.3% | $0.91 | +38% | about 8.9k tokens |
| 8x | 2,400 / 1,200 | 4,000 / 1,600 | 18.6% | 10.3% | $1.00 | +53% | about 16k tokens, $0.033 |
| **16x, chosen** | 4,800 / 2,400 | 8,000 / 3,200 | 7.7% | 3.6% | $1.07 | +64% | about 29k tokens, $0.06 |
| whole | | | 0% | 0% | $1.13 | +72% | unbounded |

A real prompt's median is 112 characters (p90 3,563), an answer's 596 (p90 2,621), so most turns are whole at any tier; the tiers differ in the long ones. At 16x an average call reads about 4,900 input tokens instead of 2,800, and a turn is still bounded, so one pasted log cannot make a call unbounded. These shares were measured when every prompt was cut at 16x: the user's own prompt now keeps its first 15,000 and last 5,000 ([How a turn is filtered](#how-a-turn-is-filtered)), so it is cut less than the table says, and 16x stays the cut of the answer and of any other origin's prompt.

The cost and the cut are measured in use, not only here: every model call logs one `call.cost` record (`completeRecorded`) with its kind, model, outcome, `ms`, tokens (`inTok`, `outTok`, `cacheRead`, `cacheWrite`), its price in dollars (`usd`, `priceCall`, left out for a model with no price), the turns its memory held (`memTurns`), their prompt and answer characters kept (`memKept`) and before the cut (`memFull`, `memoryStats`), and the prompt's size (`promptChars`). The price is buddy's own list-price table (`src/prices.ts`): the model is an alias, an id or an id with an 8-digit date, and a cache write bills at the 5-minute rate, as the usage does not split it. `npm run audit` (`scripts/audit.mjs`, `-- --since 24h|7d`, or log files named; with none, every rotated `buddy.log.N` and then `buddy.log`) totals them per day, per kind and overall: calls, failures, tokens, the cost, the turns remembered and the share of their text cut. The cost is the logged `usd`; an older line without one is priced from the same table, `src/prices.ts` (`priceCall`), which the audit imports, and a `priced:` line counts the calls priced each way. With no log it exits 1 naming where it looked; a bad `--since` exits 2; a line that does not parse is named; a model with no price is named and left out of the cost, a row that left such calls out marked `*` and one with none priced `-`.

## The story form

The memory is all the buddy reads of the chat: it stands in for the whole conversation. The last turn it renders, the one a call is about, stays as filtered above; every turn before it is told as a story, cut to what steers the buddy (`render`, `turnLines`):

| Part of an older turn | Kept |
| --- | --- |
| the prompt | the user's own (`sent:`) its first 3,000 and last 1,000 characters (`STORY_USER_PROMPT_HEAD`, `STORY_USER_PROMPT_TAIL`); a taken suggestion's, any other origin's, a signed message's and the `suggested:` line its first 600 and last 200 (`STORY_PROMPT_HEAD`, `STORY_PROMPT_TAIL`) |
| a prompt the user added while Claude worked | its line, label and position included, to the first 3,000 and last 1,000 characters (`STORY_USER_PROMPT_HEAD`, `STORY_USER_PROMPT_TAIL`) |
| a signed message delivered while Claude worked, what Claude wrote mid-turn, an agent's brief or report | each line, label included, to the first 400 and last 100 characters (`STORY_ADDED_HEAD`, `STORY_ADDED_TAIL`) |
| what Claude did | its line whole (`STORY_DID_STEPS` null); a number there names only that many steps and counts them all, `Claude did 10 steps: a; b; [cut]` (`didLine`) |
| the numbers | only its failed tool calls, when any: `2 tool calls failed.` |
| the answer | its first 500 and last 300 characters (`STORY_ANSWER_HEAD`, `STORY_ANSWER_TAIL`) |
| the buddy's exchanges | whole and in order, canned lines included |

A compaction before the last turn keeps its head line, then its summary and the exchanges after it, canned lines left out, cut to the first 4,000 and last 1,000 characters (`STORY_COMPACTION_HEAD`, `STORY_COMPACTION_TAIL`). A compaction that is the last turn, and what was said before any turn, stay as they are.

Replayed on 189 real end-of-turn calls, the story form read 27.8% fewer input tokens and the reactions held; dropping the canned lines as well lost a catch that spanned turns, so they stay. The cut is made when the prompt is rendered, never in what is stored: `memory.json` keeps each turn as filtered above, so a turn read whole as the last is cut only once a newer one follows it. `call.cost`'s `memKept` and `memFull` count the stored turns; `promptChars` is what was sent.

## Where it is kept

Each chat has one file in its own folder, beside its transcript: `{config}/projects/{project}/{session id}/buddy/memory.json` (`chatFolderFor`, `src/chatFolder.ts`), holding `version: 2`, when it was last written (`at`), the chat's newest turn number (`turnNo`), the blocks, the live memory items (`items`), the newest 20 ended ones (`ended`), and how many times the buddy has named each live rule broken (`strikes`, by rule key, [Steering](./voice.md#steering-the-users-rules)) (`Stored`); a stored strike that is not a rule key with a positive whole count is dropped (`strikesOf`). A stored item or ended record that does not read is dropped and counted (`itemsOf`). `{config}` is `CLAUDE_CONFIG_DIR`, else `~/.claude`; `{project}` is the folder holding the transcript `{session id}.jsonl`: the one named from the session's root (every character but a letter or digit made `-`), else from its working directory, else any project folder holding it (a path too long to name so). Before the transcript exists (a new chat's start) it is the root's, and the adapter looks again at the next read. The chat's round files (`saveRounds`) go into the same folder.

Beside it, `memory.md` (`MEMORY_TEXT_FILE`) is the memory for you to read (`memoryText`): the heading `# What {name} remembers`, a line saying when it was rewritten and that {name} reads its live items and the turns below before every reply while the ended items are kept for you, then `## Items, by kind (age: turns since it last changed)`, each kind under its own heading with its items' keys (a rule as its quoted words and what it covers), then `## Ended, newest first`, each with its reason and turn (`itemsText`), then the timeline as `render` gives the character drawn now. The adapter writes it after every write of `memory.json`, on the same chain (`writeMemoryText`), and again when the drawn character changes, since the heading and the exchanges are the drawn character's: a pick, `/buddy reload`, a session start (`loadMemory`). A failed write logs `writing memory.md failed: {err}` and never throws; `memory.json` stands without it, and the next write tries again. The drawer's last row names its absolute path, `memory  {path}`, once it is written; before, `memory  not written yet: {name} writes it at its first turn`.

- **Per session.** The adapter asks `$.session.id()` before every read and loads the record again when the id changes. A `/clear` moves the process to a new session id, so it starts with no memory; a resume moves it to the resumed session's id, so that chat's memory comes back with it.
- **Exchanges per character, items per chat.** A character reads only its own exchanges (`render`), so a switched character never claims another's words, and switching back finds them again; the turns and the memory items are the same for every character.
- **In the chat's folder.** It survives `/reload`, restarts and a reopened chat: the session start loads it (`loadMemory`, for a hidden buddy too), and opening the drawer loads it, so the drawer's thread shows it at once. It lasts as long as the chat, and deleting the chat's folder deletes it.
- **Moved from the store.** Before 1.0.0 it was kept in `$.store` under `chatTurnsToRead:{session id}` (`storeKey`), 20 sessions at most. A chat's first read with no `memory.json` reads that key, writes the file, and deletes the key (`chatTurnsToRead.moved`); other chats' keys wait until those chats are opened.

Every read and write goes through one chain, in the order made, so a turn is filed before its end-of-turn call reads the memory, and an answer is saved before the next question reads it (`chainChatTurnsToRead`, on `chained`).
A link's deadline counts only its own run: a write gets 60 seconds (`CHAT_TURNS_TO_READ_WRITE_DEADLINE_MS`), a read what is left of its caller's deadline. A link still running at its deadline is abandoned, said once, and the chain goes on; a read whose caller gives up while it still waits is dropped unrun (`chatTurnsToRead.dropped`), never said failed.
A write that failed or was abandoned is made again 5 seconds later (`CHAT_TURNS_TO_READ_RETRY_MS`), so the reads queued meanwhile go first, 3 tries in all (`CHAT_TURNS_TO_READ_WRITE_TRIES`), and only while the next main turn has not started and the conversation is the same (`changeChatTurnsToRead`); the change is applied to the timeline once, never twice. `chatTurnsToRead.retry` logs each try as `trying`, `landed` or `skipped`, and a retry that lands clears the failure the next reply would have said.
An abandoned link writes nothing once it lands: a late store read never replaces the timeline a later link loaded, and at most one store write per session is in flight (`latestWrites`), so a late write never lands over a newer one.

## How it reaches the model

`render` turns the memory items and the timeline into one block, addressed to the character as "you", the way the system prompt addresses it; the user is always "the user", Claude always "Claude":

```text
Your memory (one item per line: key · text or words · from · age in turns since it last changed):
rule.no-push · don't push until I say so · user · 1
fact.session-cookie-refresh · The session cookie was never refreshed. · shown · 0

What you remember, oldest first:

Before those turns:
- You said: Quack!

Turn 1. The user asked Claude:
suggested: none
sent: fix the login bug
Claude wrote mid-turn, after 3 tool calls: The login test fails: the session cookie is never refreshed.
Claude did: read auth.ts, session.ts [call 120 · output 8.4k chars]; Run the auth tests [call 90 · output 2.1k chars] (failed: exit 1: FAIL tests/auth.test.ts > login keeps the session); edited session.ts [call 640 · output 80 chars]; Run the auth tests [call 90 · output 1.2k chars]
1 tool call failed.
Claude answered:
Fixed it: the session cookie was never refreshed.
- After this turn, you commented: Tests pass, but the lockfile moved.
  With it, you suggested the user's next prompt: commit the lockfile
- The user asked you: remember pineapple
  You answered: Pineapple, noted.

Turn 2. The user asked Claude:
suggested: commit the lockfile
sent: commit the lockfile
Claude did: Commit the lockfile [call 70 · output 140 chars]
Numbers: 11s, after a 1m05s pause · 2 model requests · 1 tool call (Bash 1) · 1 commit · tokens 250k in (99% cached), 90 out · $0.03 · context 39% full of 200k
Claude answered:
Committed.
```

A question that got no answer reads `You gave no answer.` under it; a turn of the user's reads `suggested:`, the buddy's suggestion that was in the prompt box when the user sent it (`none` when there was none), then `sent:`, what the user sent, so the model sees what it suggested apart from what the user chose: the same text for a suggestion taken unedited (filed `from: taken-suggestion`, `TAKEN_SUGGESTION`, and so never counted as typed by the user, nor are its claims taken for the user's), the suggestion at the start of what was sent for one extended, and an older turn filed as taken before `suggested` was kept shows its prompt on both lines; told as an older turn, each line keeps its first 600 and last 200 characters; a buddy's prompt it wrote but never sent reads `… you wrote Claude a prompt, never sent because the chat moved on: {prompt}` among that turn's exchanges; a turn whose prompt was not the user's reads `Claude was sent, not by the user ({origin}):`, or `Claude was sent, by a sender you did not see (most often the user's own slash command or skill, or a prompt sent while you restarted):` when its origin was never seen, which a slash command or skill (its turn text differs from what was submitted) and a hot reload both cause, so the buddy never reads an unseen sender as a stranger. A plugin hot reload (a `settings.json` edit, `/reload-plugins`) empties the prompt ledger, so the turn running then ends with no prompt on file: its prompt is read back from the transcript, the last user message that is neither a tool result nor a local command's output, and with it the steps of every tool call the assistant messages after it hold, a failed one with why, since the reloaded buddy heard none of the calls before the reload (`lostTurnOf`, `$.session.messages()`), its origin still unknown; each read logs `prompt.backfill` (`found` or `none`, with the steps read back), and a failed read is said and logged as a failure, the turn then reading `(not seen)`.

| Call | What it gets |
| --- | --- |
| a question | the block, then the question (`questionPrompt`); its system prompt carries the memory rule (`oneLineSystem`, `memoryRule`) |
| the end-of-turn call | the block, the turn just ended its last, then a pointer to it (`turnPrompt`, `JUST_ENDED`); the tally counted here only when the block misses that turn |

The memory rule tells the character how far its memory reaches, in turns, and to say in character that its short-term memory doesn't reach that far when asked about anything older, never guessing or making it up.
The block is read once, when the question is asked, so it holds what came before the question; the question joins the timeline with its answer.

## The option

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `chatTurnsToRead` | number | `4` | how many of the main chat's latest answered turns the buddy remembers, with what it and the user said after each; 1 to 10 |

A value that is not a whole number from 1 to 10 is ignored by name and remembers 4: `option chatTurnsToRead ignored: {value} is not a whole number from 1 to 10; reading 4`.
The line reaches the log at session start, the first greeting's bubble once, and `/buddy help`, as every option's error does.
Lowering it mid-session reads only the newest turns at once; the file drops the rest at the next turn.

## Errors

A `chatTurnsToRead` that cannot be read, saved or pruned never disappears in silence.
The failure is logged, and the next question's reply carries it: `Asked {name}. (Its chatTurnsToRead: {what} failed: {why})`.
A stored record that is malformed keeps what still reads and says how many entries it dropped (`chatTurnsToReadOf`); a record of another shape is said not to be a `chatTurnsToRead` record; nothing stored is an empty memory, not an error.

## Decisions

- **One timeline, one window.** Rejected: the chat's turns and the buddy's own exchanges as two lists with two sizes. The buddy then remembered comments about turns it could no longer see, and could not tell which turn a comment was about or whether its suggestion was taken; in one timeline each comment sits under its turn, and the prompt that follows a suggestion is the next turn.
- **What Claude did, as its descriptions.** Rejected: a tool's output or a diff, which costs thousands of tokens and is noise to a one-line comment; and only the tool counts, which say how much was done, never what. A shell command's description is Claude's own one-line account of it.
- **The start and end of the answer.** Rejected: its end alone. Claude says what came of a turn first; a long answer lost its conclusion and kept its closing lines.
- **A wide cut, 16x.** Rejected: 300/150 and 500/200, which cut 60% of real turns and lost 71% of their text, and no cut at all, which lets one pasted log make a call unbounded. 16x kept 96% of turns whole for 64% more per call when it cut every prompt ([the tiers](#how-much-of-a-turn-is-kept)); `npm run audit` measures what it costs and cuts in use.
- **The user's prompt whole to 20,000.** Rejected: the user's prompt at 16x like any other origin's. The user's ask is what every reaction is judged against, and a long one lost its middle before the buddy read it; other origins' prompts keep 16x.
- **Truncation, never a model summary, of briefs, reports and signed messages.** Rejected: a Haiku summary of each. A truncation experiment over real agent reports (R1) found the summaries invented statements the text never made, 48 and 50 over the two instructions tried, where a truncation invents none; and a summary costs a model call per view. Every view is cut to its start and end and marked `[cut]`, and the model is told a cut hides nothing as evidence.
- **A large report keeps 2,400 and 800.** Rejected: 600 and 200 for every report, and 3,000 and 1,000 past 10,000 characters. R1's five reports over 10,000 kept 29 of their 279 facts (10.4%) at 600/200 and 74 (26.5%) at 2,400/800, near the report class's weighted recall at 600/200 (29.9%) and under a third of it; 3,000/1,000 adds 5 points for 25% more characters.
- **A brief as its first line and last 3 lines.** Rejected: a brief cut by characters. Its first line is the ask and its last lines what the agent must return, the two parts the user reads to know what was delegated.
- **Your words and its words whole.** Rejected: folding each exchange to 160 characters and keeping 10 per turn. What you told the buddy, and what it told you, is the thread you hold it to; a cut answer quoted back is a wrong answer.
- **Older turns as a story, the last whole.** Rejected: every remembered turn at the wide cut, which spent most of a call's tokens on turns the call is not about; and a story without the canned lines, which lost a catch that spanned turns. The last turn is what the call reacts to, so it keeps its numbers and its full text; an older one keeps what steers: the user's words, the start and end of Claude's answer, its failed calls, and everything the buddy and the user said.
- **A compaction as a turn.** Rejected: ignoring it. After a compaction Claude holds only its summary; a buddy that never saw it comments on a chat that no longer exists.
- **Retry the write while the next turn has not started.** Rejected: one try in 30 seconds. A write lost to a slow store left a hole in the memory; retried later than the next turn's start it would file a turn out of order.
- **Measured in turns.** Rejected: counting exchanges. A turn is what the user thinks in, and the buddy can say how far back it remembers in the same words.
- **It knows its reach.** Rejected: a memory the model is not told the size of. Asked about an older turn, it guessed; told its reach, it says it doesn't remember.
- **Recent turns in the prompt.** Rejected: a model-written summary of the conversation. A summary costs one more call per turn; the timeline costs nothing to keep and a few thousand tokens at most to send.
- **Every call carries it.** Rejected: relying on the chat's own record. A `/buddy` answer is drawn only in the bubble and never lands in the main transcript, where the chat holds only the command and its `Asked {name}.` reply; so without the timeline no call could see what the buddy said.
- **A turn's `commentAfterEachTurn`, warning and `suggestNextPrompt` in one exchange.** Rejected: one exchange each, or the suggestion kept as a line. A `suggestNextPrompt` was put in the prompt box, never said in the bubble, and in the user's words, not the character's; apart, the model had to guess which suggestion came with which comment.
- **The character is "you", the user is "the user".** Rejected: `You:` for the user and the character's name for its lines. The prompt calls the character "you" everywhere else, so `You:` for the user's lines invited the model to take them as its own.
- **Kept in the chat's own folder.** Rejected: plugin memory only, since a `/reload` would forget the thread mid-conversation and a resume could not bring its chat back; and `$.store`, which 0.3 used, since one store shared by every chat had to be capped at 20 chats, so a reopened older chat had lost its memory, and a chat's memory outlived the chat. The chat's folder already holds the transcript the memory is read from.
- **Per session and per character.** Rejected: one global timeline. A new session's buddy would recall another chat, and a switched character would quote another's words as its own.
- **Memory items per chat, edited by key and checked in code.** Rejected: the 1.1 notes, at most 8 per character, rewritten whole by the model at every turn. A rewrite could drop or reword a standing order, a guess could harden into a fact, a summary's or a peer's orders could become a rule, and a switched character lost them; keyed edits leave untouched items as they are, a rule must quote the user's typed words, and doubts expire.
- **A small default and a hard cap.** Rejected: unbounded memory. Every remembered turn is sent with every call.
